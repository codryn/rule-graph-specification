# Security Policy

CRGS is primarily a specification repository, but security still matters because the project ships schemas, tooling, and reference validation logic.

## Reporting

Do not open public issues for suspected security problems in tooling, CI, published packages, or repository automation.

Instead, contact the maintainers privately and include:

- a concise description of the issue
- affected files or packages
- reproduction steps or proof of concept
- impact assessment
- any suggested remediation

## Scope

Security reports are especially relevant for:

- validation tooling
- package publishing configuration
- workflow automation
- malicious data handling risks in example or reference code

Specification disagreements or schema strictness concerns should usually be filed as normal design issues unless they create a real exploit path.
